\# ADR-004: Перевод репозитория в публичный доступ и настройка правил защиты ветки main



\- \*\*Статус:\*\* Принято

\- \*\*Дата:\*\* 2026-11-23



\## Контекст



На бесплатном тарифе GitHub расширенные правила защиты ветки `main` (ruleset / branch protection) доступны для публичных репозиториев. Для соблюдения процессов командной работы, ревью и автоматических проверок репозиторий должен быть открытым, при этом без утечки секретов, персональных данных и закрытой информации.



\## Решение



1\. Провести проверку репозитория и истории коммитов перед сменой видимости.

2\. Перевести репозиторий в статус \*\*Public\*\*.

3\. Включить правила защиты ветки `main` и настройки Pull Request (только squash merge, автоудаление веток, обязательное ревью и проверка `quality`, запрет `force push` и удаления ветки).

4\. Зафиксировать правила работы в `CONTRIBUTING.md`, шаблон PR и workflow релиза.



\## Результаты проверки перед публикацией



\- \*\*Секреты и ключи:\*\* проверено — ключей, паролей и токенов в репозитории нет.

\- \*\*Персональные данные и закрытые материалы:\*\* проверено — посторонних контактов и закрытых данных нет (указаны только логины GitHub участников команды).

\- \*\*Лицензии и данные:\*\* проверено — файл `LICENSE` в корне и `data/README.md` на месте, ограничения источников и данных учтены.

\- \*\*Журнал ИИ и протоколы встреч:\*\* проверено — лишняя информация отсутствует.



\## Последствия



\- Код, история коммитов, задачи и ревью видны публично; авторство фиксируется историей Git и PR.

\- Прямой `push` в `main` заблокирован даже для владельца репозитория (список обхода пуст).
