# ADR-004: Перевод репозитория в публичный доступ и настройка правил ветки main

- **Статус:** Принято
- **Дата:** 2026-11-23

## Контекст

На бесплатном тарифе GitHub расширенные правила защиты ветки `main` доступны для публичных репозиториев. Для работы по правилам репозитория, ревью и автоматических проверок репозиторий должен быть публичным при соблюдении требований безопасности, лицензий и конфиденциальности.

## Решение

1. Провести проверку репозитория и истории коммитов перед сменой видимости.
2. Перевести репозиторий в статус **Public**.
3. Настроить Pull Requests (разрешить только squash merge, включить автоматическое удаление веток после слияния) и правила защиты ветки `main` (1 одобрение, снятие одобрения при новых коммитах, закрытие обсуждений, обязательная проверка `quality`, запрет `force push` и удаления ветки, линейная история, пустой список обхода).
4. Зафиксировать правила работы в `CONTRIBUTING.md`, шаблон PR и workflow релиза.

## Результаты проверки перед публикацией

- **Секреты и ключи:** проверено — паролей, токенов и ключей доступа в репозитории и истории коммитов нет.
- **Персональные данные и закрытые материалы:** проверено — телефонов, адресов, личных почт и закрытых материалов заказчика нет (указаны только логины GitHub участников команды).
- **Данные и лицензии:** проверено — обработанные слои соответствуют лицензиям источников и ограничениям, `data/README.md` и `LICENSE` в корне присутствуют.
- **Журнал ИИ и протоколы встреч:** проверено — лишняя или конфиденциальная информация отсутствует.

## Последствия

- Код, история коммитов, задачи и ревью открыты для просмотра; авторство фиксируется историей Git и PR.
- Прямой `push` в `main` заблокирован для всех участников, включая владельца репозитория (список обхода пуст).
